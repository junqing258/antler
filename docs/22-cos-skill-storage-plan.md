# 平台 Skill 存入腾讯云 COS 的实施方案

## 目标与范围

将平台技能库上传的 Skill 完整文件集存入腾讯云 COS，数据库保留技能元数据、权限、绑定关系和存储指针；运行时仍将技能安全地展开到服务端本地缓存。后端配置从现有根目录 `.env` / 进程环境读取，部署沿用 `.env.deploy` 的覆盖方式。前端 API、ZIP 上传格式及权限行为保持兼容。

本方案的 Skill 指平台技能库（`/api/skills`）中的技能。workspace、user、bundled 技能仍由 `SkillRegistry` 从各自本地目录发现；如果也需要跨设备同步这些技能，应另行设计来源、覆盖优先级和权限。

## 当前实现

- `PlatformService.upload` 校验 ZIP 后在数据库事务中写入 `skills` 和 `skill_files`；文件正文目前以 `SkillFile.content` 存储。
- `ensureCache` 从数据库重建 `.antler-platform/skills/<id>`，校验 `filesFingerprint` 后通过临时目录替换缓存。技能调用依赖目录和资源文件，不能仅存储 `SKILL.md`。
- `SkillLocks` 是进程内读写锁；运行期间的读租约防止同进程中上传或删除改变正在使用的目录，但不提供跨实例协调。
- `migrateFileSkills` 启动时将旧磁盘布局导入数据库；改造时必须区分已经迁入 COS 的记录，避免误判并标记 broken。
- `config/env.ts` 已加载根目录 `.env`；当前工作区有会话 COS 配置及尚未纳入版本控制的 COS 客户端工作，应在实现时以合并后的实际状态为准，避免覆盖这些改动。现有客户端接口为字符串 JSON，不可直接当作二进制文件接口使用。

## 存储与配置

建议新增 `ANTLER_SKILL_STORAGE=database|cos`，默认 `database`，只决定新写入的目标；已有技能按每条记录的存储标记读取，不能因修改开关而丢失。新增 `ANTLER_SKILL_COS_PREFIX=antler/skills/v1`，与会话前缀独立。复用现有配置名称 `COS_SECRET_ID`、`COS_SECRET_KEY`、`COS_REGION`、`COS_BUCKET`，临时凭据使用可选 `COS_TOKEN`；`COS_SCHEME`、`COS_ENDPOINT` 沿用现有配置。实际进程环境优先级遵循当前加载器，部署时 `.env.deploy` 覆盖 `.env`。

启用 COS 或数据库中存在 COS 技能时，缺少必要配置必须启动失败或明确拒绝对应读取，不能静默回退。存储桶使用私有访问，服务端通过最小权限凭据访问技能前缀；不得把凭据、签名 URL、对象内容写入前端、日志或错误响应。更新 README 和 `.env.deploy.example`，只提供占位符，不修改真实 `.env`。

每个已验证文件集作为一个不可变 JSON 对象，键形如 `${prefix}/${skillId}/${operationId}.json`，两个 ID 均由服务端生成。对象含格式版本及按路径排序的文件项，每项含相对路径和 base64 正文；沿用 `filesFingerprint` 对解码后的文件集校验，不能用对象 ETag 替代现有指纹。限制编码前后的对象大小，读取时重新执行路径、文件数、单文件及总大小限制，拒绝重复路径和非法 base64，再验证指纹及 `SKILL.md` 元数据。现有 ZIP 上限与解压限制继续生效。此结构支持二进制资源且单对象发布，后续格式变更使用新版本读取器。

数据库新增存储类型和 COS 对象键；旧行默认 database，COS 行的键必须存在。元数据、指纹、存储类型、对象键在同一数据库事务中更新；不把新 COS 技能的文件正文继续写入 `skill_files`。数据库迁移应保留旧表，直至迁移、回滚和备份保留期结束。

## 写入、读取和删除

1. 上传或更新先按现有规则解析验证 ZIP，生成不可复用的操作 ID 和对象键。在数据库中持久记录上传意图和目标键后，将完整对象写入 COS 并回读验证；超时结果不确定时用同一键读取并验证，不得假定成功或换键盲目重试。
2. 持有技能写锁，数据库事务重新检查所有权、名称及预期旧指针，原子提交新元数据和指针，同时记录旧对象清理任务并完成上传意图。事务失败或结果不确定时查询意图及当前指针对账；不删除可能已提交的对象。成功后尽力刷新缓存，刷新失败由读取路径自愈，不能把旧缓存当作新版本。
3. 读取先根据数据库存储标记选择数据库或 COS，校验文件集指纹和元数据，再以现有安全写入和原子目录替换方式重建缓存。已标记 COS 的对象缺失、损坏或不可达时明确报错和告警，不回退旧数据库正文或返回空技能；区分暂时性服务故障与确认的数据损坏，避免把短暂网络故障永久标记 broken。
4. 删除仍检查 owner 和 Agent 引用。数据库事务中删除技能记录并持久保存其 COS 键的删除任务；任务表不能随 Skill 级联删除。事务提交后幂等删除对象及本地缓存，失败重试；404 按已删除处理。删除成功响应的语义为技能已不可访问且清理任务已持久化，COS 在线对象删除由任务完成并可观测。
5. 恢复任务按持久意图处理未完成上传、旧版本和删除；仅清理已确认不再被数据库引用且无在途操作或读取租约的对象。COS 查询失败或数据库状态不明时保留对象并重试。上线前确定超时、重试、队列容量、告警和孤儿清理宽限期；版本控制、备份及物理删除遵循单独保留策略。

第一版明确仅支持一个 backend 实例对同一数据库和缓存目录执行技能操作；维护迁移也必须停写。进程内锁不能保护其他实例或独立清理器。若要支持多实例，必须先实现数据库级写入互斥、跨实例运行读取租约和受协调的延迟清理，并测试上传、删除与长时间运行之间的竞争；仅靠数据库条件更新不足以保护正在使用的本地缓存和旧对象。

## 历史数据迁移与回滚

1. 备份数据库和旧技能目录并验证恢复；先部署兼容 database/COS 双读的版本及数据库迁移，保持默认 database 写入。
2. 在停写维护窗口执行显式、可重复运行的迁移命令：逐条读取 `skill_files`，校验路径、文件限制、元数据及现有指纹，按上传意图流程写 COS，回读核对文件数、字节数和指纹，再以旧存储标记及指针为条件更新数据库。失败项保留 database 来源并报告 ID 和错误类别，不输出正文或凭据。
3. 清空各实例缓存后，从 COS 验证列表、资源读取及执行；检查迁移报告并切换 `ANTLER_SKILL_STORAGE=cos`。未迁移项继续从数据库读取，明确重试负责人。COS 已存储项在切回 database 默认值后仍从 COS 读取。
4. 回滚到旧版本前，停写并将所有 COS 技能完整回填 `skill_files`，校验指纹、事务切换标记，再恢复旧版本；不能仅修改环境变量。保留数据库备份、COS 对象和旧版本读取能力至回滚窗口结束，之后通过单独的受控操作清除旧数据库正文。

## 实施与验收

- 抽出技能文件存储接口，提供数据库及 COS 实现；为 COS 客户端增加适用的受限读写能力或复用稳定的共享客户端，避免复制会话存储协议。改造 `PlatformService`、启动迁移逻辑、配置校验、Prisma schema 和迁移脚本。
- 覆盖上传、更新、删除、权限与绑定约束、资源文件和二进制往返、空缓存重建、重启恢复、旧数据迁移及回滚。注入 COS 404、超时、限流、损坏、数据库事务失败和进程中断；验证不丢失已提交版本、不会误清理新对象或泄漏凭据。
- 测试并发更新、运行中更新/删除、缓存指纹不匹配，以及重复执行迁移和清理任务；验证对象与数据库可对账，暂时故障不会误判成永久损坏。
- 运行 `pnpm check`、`pnpm test`；在隔离测试桶实测上传、回读、运行、重启及删除，核实部署环境配置和最小权限。无测试桶凭据时只能完成模拟测试，不能声称真实 COS 联通已验证。
