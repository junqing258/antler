# Pi 依赖升级方案(0.84.3 → 1.1.0)

> 状态：**待实施**
> 范围：仅 `backend/`;前端与部署脚本不涉及。

## 1. 目标与背景

后端 Agent 运行时依赖 `@earendil-works/pi-agent-core` 与 `@earendil-works/pi-ai`,当前锁定 `^0.84.3`,拟升级到 `^1.1.0`(2026-10-07 发布)。1.x 是首个正式大版本,跨 0.85–1.1 共十余个版本,包含库 API 的破坏性调整。本方案基于对两版本 npm tarball 的 `.d.ts` 全量 diff 与 release notes 的核对,梳理影响面与迁移路径。

## 2. 版本差异核对结论

### 2.1 影响后端的破坏点

**pi-agent-core 删除 `harness/` 导出面(影响最大)**

0.84.3 的 `dist/index.d.ts` 导出整套 `harness/*`,1.1.0 全部移除,包括后端 skills 模块在用的:

- `Skill` 类型(`name`/`description`/`content`/`filePath`/`disableModelInvocation`)
- `loadSourcedSkills(env, inputs)` — 基于 `ExecutionEnv` 抽象的异步技能加载
- `formatSkillInvocation(skill)` — `load_skill` 工具的输出格式化
- `ExecutionEnv`、`FileInfo`、`FileError`、`ok`/`err` — `RestrictedSkillExecutionEnv` 的整套基础

同时删除 `./node`、`./session/testing` 子路径导出及 telemetry 再导出(后端未使用)。

**Agent 循环改为 transcript 模式**

- `StreamFn` 的 context 参数类型由 `Context`(`{ systemPrompt?, messages, tools? }`)变为 `TranscriptContext`(branded 类型,只能由 loop 构造,仅暴露 `messages`)。
- system prompt 与 tools 改由 transcript 内的 system message 承载;`initialState.systemPrompt`/`tools` 语义变为"播种首条 system message",`messages: []` 起步时行为等价。
- `AgentState.systemPrompt` 变为 readonly(后端只读使用,无影响)。
- 生命周期回调更名:`shouldStopAfterTurn` → `finishTurn`,新增 `prepareRequest`(后端均未使用)。

**skills API 迁至 `@earendil-works/pi-coding-agent`,且形态不适用**

新 `loadSkillsFromDir({dir, source})` 为同步直读文件系统,无 `ExecutionEnv` 沙箱抽象;新 `Skill` 不含 `content` 字段(仅元数据);诊断结构改为 `ResourceDiagnostic { type, message, path?, collision? }`,无 `code` 字段。该包是重型 CLI 包(含 bundle、bun 运行时等),不适合作为后端依赖。

### 2.2 核对后确认无影响的点

| API | 结论 |
| --- | --- |
| `Agent` 构造 / `subscribe` / `prompt` / `abort` / `state.errorMessage` / `state.messages` | 不变 |
| `AgentEvent` 各 variant(`message_update`、`turn_*`、`tool_execution_*` 等) | 不变,仅 `tool_execution_end` 新增可选 `durationMs` |
| `AgentTool.execute(toolCallId, params, signal?, onUpdate?)` | 签名不变;`AgentToolResult` 仅新增可选 `structuredContent`/`isError` |
| `pi-ai` 的 `providers/anthropic`、`providers/openai` | 声明文件零 diff;`streamSimple` 的 `apiKey`/`headers`/`signal`/`timeoutMs` 均在 |
| anthropic catalog 模型 id | JSON key 带 `chat:` 前缀但 `id` 字段不带;现有 fallback `claude-sonnet-4-20250514` 新旧 catalog 均不存在,行为不变(回落 `getModels()[0]`) |
| `adapter.run()` 返回的 messages | host-runtime 只消费事件流,不使用返回值;transcript 含 system message 不影响持久化 |

`host-runtime.ts`、`workspace-tools.ts`、`tavily-search-tool.ts`、各测试文件**无需改动**。

### 2.3 间接变化

- pi-agent-core 1.1.0 锁定 `typebox 1.3.27`;后端直接依赖为 `^1.0.61`。为避免双版本并存导致 `AgentTool<TParameters extends TSchema>` 类型不兼容,后端 typebox 对齐到 `^1.3.27`(后端仅用 `Type.Object/String/Number/Optional`,API 稳定)。
- pi-ai catalog 新增模型(claude-opus-4-7/4-8、claude-fable-5-1、claude-haiku-5-5 等),服务端默认模型能力随之扩充,无需代码改动。

## 3. 迁移方案

### 3.1 依赖升级(`backend/package.json`)

```
@earendil-works/pi-agent-core  ^0.84.3 → ^1.1.0
@earendil-works/pi-ai          ^0.84.3 → ^1.1.0
typebox                        ^1.0.61 → ^1.3.27
```

### 3.2 skills 模块本地重写(主要工作量)

已确认方向：**不引入 pi-coding-agent,本地重写技能加载**,完整保留现有安全语义(根目录 containment、realpath 校验、大小上限、只读)。

- **`skills/types.ts`**:删除 pi 的 `Skill` 导入,定义同构本地类型 `{ name, description, content, filePath, disableModelInvocation? }`。
- **`skills/skill-registry.ts`**:删除 `RestrictedSkillExecutionEnv` 整个类(约 130 行)及 `loadSourcedSkills`/`ExecutionEnv`/`FileError`/`ok`/`err` 依赖;新增本地异步加载函数——对每个候选目录 `realpath` 后用现有 `contained()` 校验仍在对应 root 内,读取 `SKILL.md`(沿用 `MAX_SKILL_BYTES` 上限),解析 frontmatter(`name`/`description`/`disable-model-invocation`,简单 `key: value` 标量按首个冒号切分)。`list()` 返回结构、诊断 code(`skill_invalid`/`skill_too_large`/`skill_shadowed`)、shadow 优先级保持不变;旧逻辑中 `invalid_metadata` 跳过技能的行为映射为本地解析失败时同样跳过并记录诊断。
- **`skills/skill-tools.ts`**:本地实现 `formatSkillInvocation` 等价函数,输出格式与旧实现逐字节一致(避免改变模型可见内容):
  ```
  <skill name="${name}" location="${filePath}">
  References are relative to ${dirname(filePath)}.

  ${content}
  </skill>
  ```
- **`skills/skill-prompt.ts`**:不改(只消费 `SkillSnapshot`)。

### 3.3 适配层微调(`agent/pi-agent-adapter.ts`)

导入与构造不变;仅处理 `StreamFn` context 类型变更为 `TranscriptContext` 的类型适配(适配层透传 context,运行时无变化),以 `pnpm check` 结果为准做最小修改。

## 4. 验证

1. `pnpm install` — 确认 pi 解析为 1.1.0、typebox 去重为单版本。
2. `pnpm check` — 类型零错误(skills 重写 + adapter 适配的主要校验)。
3. `pnpm test` — 重点回归 `skills/skill-registry.test.ts`(frontmatter 加载、fingerprint、symlink 逃逸、`load_skill`/`read_skill_resource` 输出)与 `agent/host-runtime.test.ts`(事件映射)。
4. 冒烟:`pnpm dev` 发起一次真实会话(anthropic 与 openai 路径各一),确认流式事件、工具调用、skill 加载端到端正常。

## 5. 风险与备注

- **transcript 模式行为差异**:system prompt/tools 进入 transcript 后,provider 适配层负责回放(不支持中途 system message 的 provider 会重建首条 system message)。后端技能快照变更时是抛错重建会话而非原地改 tools,不受"工具变更广播 system message"新行为影响。
- **本地 frontmatter 解析**仅支持标量字段,与现有 fixture(`backend/skills/antler-rag/SKILL.md`、测试用例)格式一致;后续若引入复杂 YAML frontmatter 需再评估。
- 重写后 skills 模块与 pi 完全解耦,后续 pi 升级的影响面收敛为 `pi-agent-adapter.ts` 一处。
