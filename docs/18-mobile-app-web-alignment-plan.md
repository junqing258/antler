# 移动端 App 参考 Web 优化实施方案

日期：2026-11-01  
状态：首期导航与会话管理、知识库配置已实施并通过自动化验证；iOS 模拟器基线视觉验收通过，交互验收受阻于本机无 Simulator GUI，Android 交互验收按用户指示暂停。详见文末实施记录。

## 1. 目标与范围

参考所给 iPhone 16 移动端 Web 截图及当前 Web 聊天页，将 React Native App 的聊天导航、会话管理和基础视觉体验优化到一致的使用逻辑。截图主要展示打开的侧边抽屉，无法据此判断聊天内容、其他页面及动画的全部视觉细节；这些部分以当前 Web 实现为补充参考，并在实施时进行双端实机对照。

首期交付聊天页顶部导航、抽屉、新建及切换会话、会话重命名与删除、设置入口，以及安全区域、键盘和无障碍适配。保留现有 Agent 首页及其入口。知识库配置和定时任务在截图中存在，但 App 当前未提供完整对应功能：本方案将知识库列为后续阶段，定时任务管理沿用现有移动端暂不支持的范围，需另行确认产品范围后立项；首期不展示无效入口。个人区域先接入可用的账号信息和现有设置，完整个人资料编辑另行评估。

## 2. 现状与差异

| 项目 | Web 现状 | App 现状 | 计划 |
| --- | --- | --- | --- |
| 聊天导航 | 窄屏顶部菜单打开左侧抽屉，遮罩覆盖聊天页 | 聊天页上方为“← 主页”和“对话”，无抽屉 | 增加原生抽屉及标题栏，保留回首页路径 |
| 会话 | 当前 Agent 下列表、分页、新建、切换、重命名和删除 | 首页读取全部历史及分页，可打开；聊天内无列表与管理 | 抽屉按当前 Agent 加载和管理；无 Agent 的直接对话按其实际归属处理 |
| 主体 | 顶部品牌、功能入口、历史列表、底部账号和设置 | 首页有 Agent、历史和设置，聊天页单独配置 | 对齐截图层级，历史独立滚动，账号区固定底部 |
| 聊天 | Web 与原生使用共享 `ChatScreen` | 已使用共享 `ChatScreen` 和 `ChatSession` | 继续复用，集中改宿主导航和必要的跨端组件 |
| 配置 | 有知识库配置、服务地址、定时任务和设置中心 | 现有设置主要是本设备模型供应商配置 | 首期接入现有配置；其余能力按阶段实现，不冒充已支持 |

代码依据：`web/src/views/chat/chat.tsx`、`web/src/views/chat/index.tsx`、`mobile/src/app.tsx`、`mobile/src/home-page.tsx`、`mobile/src/native-chat.tsx`、`packages/ui/src/conversation-list.tsx`。既有范围及验证背景见 [React Native 迁移进度](16-react-native-migration-progress.md)。当前分析基于源码和用户截图，尚未对 App 截图或真机表现做视觉测量。

## 3. 交互与视觉规格

- 聊天页顶部放菜单按钮和当前会话标题；标题过长单行省略。菜单打开后左侧抽屉覆盖聊天，右侧半透明遮罩；点击关闭按钮、遮罩或 Android 返回键关闭。关闭后回到原会话和输入状态，不重建 session。抽屉顶端品牌可返回 Agent 首页，操作前先关闭抽屉。
- 抽屉参考截图使用浅色背景、绿色品牌、分隔线、浅灰新建按钮、灰色辅助文字与图标；顶部品牌、功能入口、历史和底部账号分区。宽度建议 `min(屏幕宽度 × 0.78, 320dp)`，小屏保留可点击遮罩；最终以设备对照调整，不直接照搬截图像素。适配横屏、动态字体及顶部/底部安全区域。
- 历史区域占据剩余高度并可独立滚动，长标题省略；当前会话标识清晰。新建会话保留当前 Agent，生成新 ID；选择历史关闭抽屉并切换。切换会话按现有运行时停止本地订阅并恢复服务端状态，不隐式取消服务端运行。
- 重命名使用跨平台输入弹窗，空值禁止提交；删除需明确确认且失败保留列表。删除当前会话成功后进入同 Agent 的新会话。加载、空列表、分页、失败重试和操作中状态均可见，避免重复提交。
- 用户信息可取得时显示头像首字母和邮箱；local 模式或无资料时显示中性占位，不推断身份。设置入口打开现有供应商配置；退出登录仍可从明确的账号入口访问。所有图标按钮具备可读标签和至少 44×44dp 触控区域，打开抽屉时限制背景交互，关闭后恢复焦点。
- 键盘出现时输入框可见，抽屉与弹窗不被安全区或键盘遮挡。流式生成、停止、历史分页、模型切换和凭据提示保持现有语义。

## 4. 实施设计

### 4.1 导航容器与原生抽屉

在 `mobile/src/app.tsx` 保留现有状态驱动导航及自动化深链，增加聊天页抽屉状态与返回首页、设置、会话操作回调；退出或切换账号时清理抽屉及账号相关状态。将 `mobile/src/native-chat.tsx` 的标题区域改为菜单与会话标题，`ChatScreen` 继续使用现有 session。新增原生抽屉组件，使用适合 RN 的模态/遮罩、动画及返回键处理；先评估现有依赖能否满足焦点和安全区域要求，必要时再引入经过 Expo 版本兼容性验证的依赖。避免为此次改造强制迁移导航框架。

### 4.2 会话数据与操作

抽取移动端可复用的会话列表数据层，统一首页与抽屉的鉴权请求、分页、错误及刷新，优先复用 `@antler/client-runtime` 已有能力；若缺少列表/变更订阅接口，在共享运行时或移动端适配层按现有平台抽象补齐，避免直接依赖 Web 的 `window`、路由和认证模块。使用服务端 Agent 过滤语义，并验证无 Agent 会话查询规则，不能把全部历史误作为单 Agent 历史。

对齐 Web 的 `PATCH /api/conversations/:id` 和 `DELETE /api/conversations/:id` 语义，包括版本冲突、404 和鉴权失败；重命名以服务端返回/重新读取为准，删除确认成功后更新列表。接入已有会话变更流或可证明等效的刷新机制，覆盖发送后标题变化、其他端更新、前台恢复和分页去重；账号切换时取消请求/订阅，防止旧账号响应写入新状态。保留首页历史入口，不重复维护互相矛盾的列表。

`packages/ui/src/conversation-list.tsx` 已有选中、重命名、删除及加载更多回调，可评估复用并补足触控尺寸、加载/错误状态及原生适配；共享组件的视觉改动须同时回归 Web。抽屉、弹窗等平台差异放在移动宿主，业务逻辑不复制到 UI 中。

### 4.3 后续功能

知识库阶段参照 `web/src/components/knowledge-configuration-link.tsx` 接入配置读取、保存、恢复默认和外部服务地址；必须保留 Key 留空不变、显式清除、错误及认证语义，并验证外链协议和打开失败处理。定时任务管理当前不在移动端范围，需单独定义创建、编辑、启停和权限范围，再决定原生实现或其他入口；未经实现不显示可点击的占位项。个人资料编辑同样在确认后单独安排。

## 5. 分阶段交付

1. **基线与设计**：采集同账号、同 Agent、同会话的 Web 和 iOS/Android App 截图，确认尺寸、状态及无 Agent 过滤规则；记录设备、系统、字体缩放、数据及截图，形成可重复对照样例。
2. **首期导航与数据**：实现标题栏、抽屉、账号/设置和返回首页；打通列表、分页、新建、切换、重命名、删除及变更刷新。确保首页、深链、认证和已有会话运行链路不回退。
3. **适配与验收**：完成键盘、安全区、长列表、弱网、跨账号、无障碍和双端视觉核查；修复问题并记录尚未验证的环境。
4. **按需扩展**：单独实施知识库；定时任务与完整个人资料在范围确认后排期。更新迁移进度和验证记录。

## 6. 验收与测试

- **视觉**：在 iPhone 16 尺寸及至少一台 Android 常见尺寸上对照 Web；检查抽屉层级、遮罩、品牌、间距、长标题、滚动和底部安全区。另测小屏、横屏及较大系统字体，不出现遮挡、截断关键操作或横向溢出。
- **交互**：菜单、关闭、遮罩、Android 返回键、返回首页和设置均可用；关闭抽屉保留草稿及运行状态。新建/切换保持正确 Agent；重命名、删除、取消、失败和当前会话删除均符合第 3 节；分页不重项且不会跨 Agent 混入。
- **一致性**：同账号跨端新建、改名、删除及自动标题更新后，打开抽屉或恢复前台能看到服务端最新状态；弱网/重连、快速切换账号和失效登录不显示旧账号数据。生成中切换与返回可恢复状态，不误发或取消。
- **输入与无障碍**：iOS/Android 键盘打开、中文输入、发送、停止和收起正常；VoiceOver/TalkBack 可识别控件及选中状态，焦点不穿透抽屉，操作目标可触达。
- **自动化**：为列表过滤、分页去重、版本冲突、删除当前会话、请求竞态和账号切换增加有意义的回归测试；为抽屉及主要操作增加组件交互测试，复用现有 `web/test/native-app.test.tsx` 等测试设施。执行 `pnpm check`、`pnpm test`、`pnpm build:mobile`；共享组件变更同时验证 Web 构建及相关测试。记录命令、结果与跳过原因。
- **设备**：至少在 iOS 和 Android 模拟器完成上述主要路径；真机及独立 Release 用目标 HTTPS 后端验证登录、SSE、后台恢复和键盘。设备或后端不可用时明确列为未验证，不以 bundle 导出代替设备验收。

## 7. 风险与依赖

- 原生模态焦点、安全区和键盘行为存在平台差异，必须以设备验证；动画不能阻塞操作或破坏无障碍。
- 列表与运行事件可能并发，分页、删除和账号切换需防旧响应与复活；以服务端版本和快照为准。
- 共享组件调整可能影响 Web，需双端回归；截图仅为视觉参考，不应为像素一致牺牲触控或系统字体适配。
- 真机、签名、目标 HTTPS 服务和测试账号是发布验证的外部依赖；当前方案不假设这些条件已经具备。
