# 自托管 Supabase 数据库连接

本地开发读取根目录 `.env`，线上部署脚本合并 `.env` 与 `.env.deploy`，后者覆盖同名变量。两个文件均不应提交到 Git。

| 用途 | PostgreSQL 地址 | 说明 |
| --- | --- | --- |
| 本地开发 | `192.168.31.120:5432` | 内网 Supavisor 会话池 |
| 阿里云 backend 容器 | `host.docker.internal:15432` | 经宿主机 FRP 转发到内网 `127.0.0.1:5432` |
| 公网事务池映射 | `47.100.210.56:16543` | 对应内网 `6543`，当前项目不使用它执行 Prisma 迁移 |

数据库为 `postgres`，连接池用户名格式为 `postgres.<POOLER_TENANT_ID>`。密码取自自托管 Supabase 配置，并进行 URL 编码。

`https://supabase.xiaoanai.top` 是 HTTP API 地址，不能代替 PostgreSQL 连接地址。公网 HTTP 网关端口为 `18000`，也不用于数据库连接。

本地需要能够访问上述内网主机。线上容器需要 Compose 中的 `host.docker.internal:host-gateway` 映射，以及两端 FRP 持续运行。此次验证发现开发电脑直接访问公网数据库端口会断连，因此本地采用已验证的内网路径。

## 表结构与权限

`pnpm --filter @antler/server db:deploy` 应用现有表结构迁移。开发启动和线上镜像启动也会执行 `prisma migrate deploy`。切换连接不会复制旧数据库的业务数据。

后端业务表启用 RLS，不提供匿名或 authenticated API 角色的访问策略；业务访问由后端 PostgreSQL 管理连接完成。不要为这些表添加公开读取策略。将来改用不绕过 RLS 的数据库账号时，需要同时设计对应访问策略。

## 验证与回退

切换后检查 backend 的数据库查询及 `/health`。线上修改前的环境文件保存在 `/opt/antler/.env.before-supabase-db-*`，权限为 `600`。

回退时恢复该环境文件并重新创建 backend 容器；旧数据库没有被搬迁或删除。不要将含数据库密码的连接串、备份文件或通知渠道凭据提交到 Git。

## 消息写入与故障降级

流式事件先进入内存并推送给当前客户端，每个运行约每 2 秒批量写入一次。一个批次只更新一次消息投影和会话同步版本；运行开始、结束时单独保存状态，结束前尝试刷完尾部事件。创建运行仍要求数据库元信息提交成功，用户消息正文采用本地磁盘存储。

消息持久化允许损失：进程异常退出时可能丢失尚未刷盘的增量；写入失败的批次直接丢弃，后续批次继续保存。每个运行最多保留 1000 个待写事件，超出后丢弃最旧的待写事件。当前进程内的实时输出和断线回放仍保留完整事件，重启后的历史及其他设备只看到已提交内容。检查点或终态写入失败会记录警告，不把模型执行改判为失败；数据库中的运行状态可能暂时落后，重启时按中断运行恢复。

Postgres 连接设置 5 秒连接超时、2 秒锁等待超时、10 秒 SQL 超时及事务空闲超时。这些限制在数据库端取消等待，防止只让 JavaScript 超时却继续占用事务锁。模型或工具执行不应放进数据库事务中。

## 本地 JSONL 历史存储

会话消息正文、运行事件和模型上下文检查点保存在后端本地磁盘。路径为 `ANTLER_PLATFORM_ROOT/storage/conversations/<用户与会话的 SHA-256>/`，每个会话包含：

- `messages.jsonl`：按批次追加的消息快照和运行事件；同一消息 ID 以最后一次快照为准。
- `checkpoint.json`：原子替换的模型上下文快照，不是用于展示的消息列表。

流式输出仍约每 2 秒刷一次，结束时尝试刷完尾部，并压缩掉过期的消息快照，保留事件回放。读取时忽略没有完整换行的尾部批次，下次追加前截掉损坏尾部。允许在进程异常退出、磁盘写入失败时丢失部分增量。消息分页按稳定的 `seq` 进行；文件权限为 `0600`，会话目录为 `0700`。删除会话会清理本地文件，晚到的事件不会重建已删除会话。

数据库继续保存会话归属、标题、执行配置、运行状态、请求去重及变更同步游标。新运行的 `runs.input` 留空，读取运行时从本地用户消息还原输入；新消息和事件不再写入 `conversation_messages`、`run_events`，检查点正文也不再写入 `conversations.checkpoint`。因此数据库短事务只更新元信息，不包含文件 IO。

新增迁移为 `20261022070000_local_conversation_storage`，给会话增加 `messageStorage` 字段。开发和容器启动时已有的 `prisma migrate deploy` 流程会应用它。已有会话首次读取、继续执行或启动恢复时，会先将数据库消息、事件和检查点复制到磁盘，再标记为 `local-jsonl`；失败时不修改存储标记，可重试。旧消息和事件表中的记录暂时保留，不自动删除。迁移完成后本地文件是消息正文的读取来源，文件丢失不会悄悄回退到旧版历史。

必须把数据库和平台目录一起备份、恢复。现有 Docker Compose 的 `./platform:/platform` 挂载已经覆盖这些文件，无需新增卷。开发环境默认位于工作区相邻的 `.antler-platform/storage/conversations/`。模型工作区不应覆盖此目录。一个平台目录仅供一个后端实例写入；本实现不提供跨主机文件共享。缺少本地检查点时，重启后的会话会明确要求新建会话，不将显示用聊天记录冒充模型上下文。
