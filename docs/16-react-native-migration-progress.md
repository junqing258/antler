## 已实施内容

### 基础设施与会话

- 当前依赖组合为 Expo SDK 58、React/React DOM 19.3.0、React Native 0.88.1 和 React Native Web 0.21.4。Web 宿主已升级 React；聊天界面已切换为共享组件（M1）。
- `packages/chat-core` 包含消息领域类型、DTO 转换、事件 reducer、快照合并、水位与斜杠命令；`packages/client-runtime` 的 `ChatSession` 管理发送、幂等重试、停止、历史分页、运行恢复和订阅。Web 与实验性移动入口消费同一 session。
- `packages/platform` 及 Web/原生适配器注入网络、认证连接、前后台通知、UUID 和流处理等能力。会话变更和 Run SSE 分别维护各自游标；复制动作经注入回调接入两端。
- 客户端凭据来源的会话检查本设备 API Key 与绑定协议、端点是否匹配；缺失时保留历史查看和运行恢复，阻止发送并提示配置（`ProviderConfigForm` 即该提示的配置入口）。该逻辑已有自动化覆盖，真实跨设备行为仍需验证。
- 实验性移动入口使用 AsyncStorage 保存普通配置、SecureStore 保存令牌及模型 Key；Supabase 模式提供邮箱密码登录（`native-auth`：登录/退出/持久会话令牌，autoRefreshToken 开启），local 模式仍手动提供访问令牌。Web 诊断入口使用浏览器存储，不等同于原生安全存储。

### 共享聊天界面

- `packages/ui` 提供消息气泡、列表、输入框、ChatScreen（欢迎页/通知/凭据入口/分页/免责声明）与 ModelPicker；Web 主聊天已默认使用共享 ChatScreen（`SharedThread` + `useChatSession`），assistant-ui 已删除。消息气泡以折叠块展示思考内容与工具调用，并有等待提示、错误/停止状态和注入式复制动作（Web 已接剪贴板，原生待接 `expo-clipboard`）。ModelPicker 在 Web 与实验入口均可用：模型列表来自 Web 供应商配置或设备配置（逗号分隔），切换语义与旧版对齐（绑定时新建会话）。
- Markdown 使用 `markdown-it` 和 RN/RNW 渲染，覆盖常见段落、强调、列表、引用、代码块、表格和 HTTP(S)/邮件链接；原始 HTML 作为文本处理，图片暂显示替代文字。语法高亮、脚注、中文强调增强、流式补全及设备表现仍待验证或实现。
- 列表按平台分流：Web 实现底部跟随和历史前插锚点，原生使用 FlatList 可见位置保持与底部跟随。组件测试覆盖部分 Web 行为，长列表、折叠内容、软键盘和原生设备尚未完成验收。
- Web 输入框支持 Enter 发送、Shift+Enter 换行、输入法组合保护和自增长；共享命令定义已接入 Web 键盘选择及原生触摸菜单。原生输入法、焦点、触摸和键盘避让需设备实测。

## 已验证与未验证

- Docker 镜像曾使用冻结 lockfile 构建，并以隔离 PostgreSQL 验证 Web 静态页面、401、鉴权会话 API 和会话变更 SSE 心跳；未运行真实模型。后续共享 UI 改动需在下一个交付检查点重新验证镜像。

## iOS 真机调试现状

**目前还没有完成真机安装或运行验证。** 已有实验性 Expo 入口和一次 iOS 模拟器 Debug 构建结果，不能据此保证真机可用。继续推进需准备可用的 Xcode 签名团队与设备、设备信任和开发者模式，并根据项目配置生成并安装开发构建；连接开发电脑时使用手机可访问的地址，而不是手机上的 `127.0.0.1`。测试需要可用的后端和相应认证/模型配置；涉及发布验收时必须使用目标 HTTPS 后端。

真机开发构建、Expo Go 或 JavaScript bundle 导出均不能替代 iOS/Android 独立 Release 安装包的鉴权 API、SSE、断线重连和前后台恢复验收。实际设备、签名及后端可用性需在执行时确认，不在本文假定已具备。

## 后续实施顺序

以下各项除第 3 条外都需要真实设备、签名团队或目标 HTTPS 后端，无法在纯本机环境执行。

1. **完成设备基线与 P0 缺口。** 准备 iOS 真机开发构建并验证安装、启动、配置、鉴权 API、中文增量 SSE、取消和前后台恢复；配置 Android 构建环境并执行同类检查。单列双平台独立 Release 与 HTTPS 验收，记录 ATS/明文配置和结果。
2. **在设备上完成 P2 验证。** 固定 Markdown/长会话样例下验证选择、链接、表格、代码高亮、脚注、流式渲染和性能；验证列表锚点、菜单、输入法、键盘避让、复制与无障碍；验证 Supabase 登录、令牌自动刷新与跨重启会话恢复。
3. **（可选，产品需求驱动）** 若产品要求移动端定时任务管理或 Agent 编辑，按共享表单状态机 + 平台能力插槽的既有模式单独立项；当前范围决策为移动端不含两者。
4. **逐域真机视觉与焦点核查。** 已共享的各域组件在真机上完成桌面与窄屏视觉、键盘焦点、无障碍核查，修复发现的问题。
5. **完成 P5 发布验收。** 完整实现原生导航与配置恢复，测试登录刷新/退出、跨账号隔离、弱网和前后台恢复；以真实 HTTPS 后端和双平台 Release 安装包验证同账号续聊、生成中切端及服务端/客户端两类凭据场景。

每个实现阶段继续运行 `pnpm check`、`pnpm test` 和受影响的构建；界面变更增加实际页面和响应式视觉核查，原生功能增加设备验证。涉及共享 workspace 依赖或镜像的变更重新执行 Docker 构建和 API/SSE 冒烟。任何测试失败、跳过项或未覆盖的平台应单独记录，不将其标记为通过。
